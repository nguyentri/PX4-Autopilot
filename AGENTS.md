# AGENTS.md — RZ/V2H PX4 + NuttX Port

Tool-neutral guide for AI agents (Claude Code, Codex, Cursor, ...). Read this
first, then open only the doc you need from the map below.

Project: PX4 Autopilot fork porting PX4 + NuttX to the Renesas RDK-RZ/V2H
(R9A09G057H). Primary flight core is **Cortex-R8 core 0 (CR8-0)**. CR8-1 and
CM33 act as IO cores over IPC. RA8E1/RA8P1 targets also exist but are not the
focus here.

## 2. Build — two different scripts

| Goal | Command (from repo root) | Output |
|------|--------------------------|--------|
| Full PX4 firmware | `./build.sh renesas_rdk-rzv2h_default` (`--list` for all targets, `--no-clean` to iterate) | `build/<target>/<target>.elf` |
| NuttX only (driver bring-up, NSH samples) | `platforms/nuttx/NuttX/build.sh <config>` | `platforms/nuttx/NuttX/nuttx/nuttx` (ELF), `.bin`, `.hex` |
| NuttX only, RA8P1 `evk-ra8p1` (EK-RA8P1) | `platforms/nuttx/NuttX/build_ra8p1.sh <config>` (same flags/exit codes; `NUTTX_DOWNLOAD_CACHE=<dir>` reseeds `RTT.zip` offline) | same as above |
| NuttX only, R-Car V4H `sparrow_hawk` (CR52-0/1) | `platforms/nuttx/NuttX/build_rcarv4h.sh <config>` (`--list`; configs `nsh`, `nsh-cr52_1`, `gpio`, `i2c`, `spi-loopback`, `openamp`, `openamp-cr52_1`, `iccom`; runs the per-core ELF window check; IPC guide `docs/renesas/rcar-v4h/ipc.md`) | same as above |
- PX4 targets: `renesas_rdk-rzv2h_{default,demo,demosih,dualcr8}`, `renesas_rdk-rzv2h-io-cr8_1_{default,demo}`, `renesas_rdk-rzv2h-io-cm33_default`. `drone`, `dshot`, `simple`, `sih`, core-only, the CR8-1 PX4IO relay and the CR8-0 `px4io_bridge` were retired 2026-11-18 (docs/evidence stay historical). `io-cm33_default` is kept but deferred: build-only, and no image talks to it since the relay removal (both CR8-1 profiles forbid `CONFIG_RZV_IPC_CR8_1_CM33`).
- `dualcr8` is the canonical exact-BOM sensor bring-up profile: one polled ICM-45686/P93, BMM150, BMP390, M10 and TFmini. CR8-0 motor outputs are disabled; commander requires first I/O status. No CR8-1 actuator pair is qualified yet. The former separate demo target was merged here; old staging evidence remains historical.
- CR8-1 `default` is the build-clean v3 supervisor candidate for `dualcr8`; zero hardware identities prevent physical resource claim. Current software evidence and open service/qualification gates: `docs/renesas/evidence/dualcr8-software-validation-261021.md`. Shared demo helpers live directly in `src/apps/` (CMake target `rzv2h_demo`).
- CR8-0 `default` is the reference drone (RDK sensor extension). It links `pwm_out` and `dshot`; `PWM_MAIN_TIM0..3` picks one at boot (default 400 Hz PWM; all four `-3/-4/-5` = DShot600/300/150). `demo` is the single-core bench drone (CR8-1 unused) and `demosih` its SIH variant; CR8-1 `demo` is the heartbeat peer of `demosih` only.
- NuttX configs: `platforms/nuttx/NuttX/build.sh --list` (e.g. `nsh-rtt`, `nsh-scif`, `ipcc`, `adc`, `canfd`, `hil-full`). `--no-clean <config>` rebuilds the same config incrementally. Exit codes: 0 ok, 1 build failed, 2 bad usage.
- Never hand-run `tools/configure.sh` + `make`; the scripts handle distclean and stale arch symlinks.
- First-time setup: `source ./build_setup.sh` (checks deps, scrubs e2studio `CMAKE_*` env vars, inits submodules).

## 3. Run and debug on hardware

- Console is **SEGGER RTT**, not UART (serial shell on SCI5 only in standalone `nsh`-style configs; SCI5 is MAVLink telemetry in PX4 images).
- Start with `platforms/nuttx/Debug/jlink-debug-preflight.py` (host-only: probe serial, owners, ports, ELF → core/RTT map;
  `--print-serial` for `JLINK_SERIAL`). Do not probe with `JLinkExe -ShowEmuList` (invalid) or `-?` (exits 1).
- RTT: `JLinkGDBServer` **cannot** bridge RTT on CR8. Use `platforms/nuttx/Debug/nuttx-rtt-bridge.sh start cr8_0 <elf>`
  (JLinkExe, serves channel 0 on `127.0.0.1:19021`), then send NSH commands with
  `platforms/nuttx/Debug/nsh_console_exec.py --marker ...` (`--marker` is required on PX4 images, which log while the shell idles).
  Stop the bridge before starting a GDB session (one probe, one owner).
- **A failed J-Link connect can reset the board** (DLL default: reset pin + cold reset; the RAM images are lost). The bridge sets
  `InhibitConnectRetries` and exits 3 on reset/connect-failure markers; after exit 3, diagnose (logs, owners, ELF/core) and recover with the guarded loaders; never blind-retry.
  Exit 3 with "held in reset or was never started" (DBGEN) means no image runs on that core; no reset was logged.
  Never connect to the CM33 (its connect resets the SoC).
- Read-only GDB snapshot: `platforms/nuttx/Debug/jlink-gdb-oneshot.py <cr8_0|cr8_1> <elf> -ex 'bt'` (`-noreset -noir -singlerun`,
  refuses mutating commands, exit 5 on reset, exit 6 when gdb reported errors). PX4 health snippets: `platforms/nuttx/Debug/rzv2h-ipc/rzv2h-px4-cr8_1-io-health.gdb`.
  Loads: `rzv2h-ipc/rzv2h-load-one-core.sh <core> <elf>` (one core) or `rzv2h-ipc-demo-load-both-auto.sh <cr8_0-elf> <cr8_1-elf>`.
- Discover `_SEGGER_RTT` from the exact loaded ELF (PX4 CR8-0 images with the 32 KiB up buffer use `0x081a8404`; older evidence shows `0x081a2400`); the NuttX demo defaults are CR8-0 `0x081A0000`, CR8-1 `0x081E0000`. J-Link devices: `R9A09G057H44_R8_0`, `_R8_1`.
- Register decode: `platforms/nuttx/Debug/svd_register_tool.py --svd rzv2h.svd ...`.
- Skills: `gdb-jlink-debug` (J-Link/GDB/RTT/SVD workflows), `audit-rzv2h-px4-nuttx-port` (cross-layer audit), `audit-ra8p1-px4-nuttx-port` (RA8P1 audit), `fw-audit`.
- Standing board authorization (local RDK board): agents need no approval for any board debugging action the task
  needs: probe attach, reads, RAM ELF loads, resets, run control, target memory/register writes and recovery reloads
  (including after a bridge exit 3). Report the effects; narrower request instructions win; sandbox/device-access
  controls are not bypassed.

## 4. Reference sources (`refs/`, local only)

`refs/` is gitignored (~1 GB). It may be missing on a fresh clone; ask the user instead of guessing.

| `refs/rzv2h_evk/<periph>/<periph>_rzv2h_evk_{cm33,cr8_0,cr8_1}_ep/` | Renesas FSP example projects per peripheral, **per core**, for the **EVK** board (not RDK). Use them for IP behavior (registers, clocks, IRQ/ELC); never take pins from their `pin_data.c`. |

The sensor extension is the CR8-0 `default` image (P94 serves CS1 there; the
legacy GY912 P94 DRDY wiring is historical). Missing generated artifacts or schematic data
do not block source/host/build work; record remaining physical qualification.

## 5. Evidence rules

- Status tiers: stub → source-audited → build-clean → bounded on-target → production
  (defined in `docs/renesas/port-status-nuttx.md`).
- A clean build, RTT output, or a static register comparison is **not** on-target proof. Do not promote a driver
  without a named board transcript.
- Update `docs/renesas/port-status-nuttx.md` / `port-status-px4-hal.md` when a driver's status changes.
