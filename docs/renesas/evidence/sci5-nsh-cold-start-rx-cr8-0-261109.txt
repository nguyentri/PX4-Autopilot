# SCI5 NSH cold-start RX board run, CR8-0, 2026-11-09
# image: build.sh nsh, sha256 20eeaacd094ef73f49b1dd78f410405a2ffa3250bb554c06fd250a39960c8495
# host: FT232 /dev/ttyUSB0 115200 8N1 raw; probe J-Link 52000195; guarded loader rc 0
# change under test: rzv_setup writes CCR3.FM and resets the FIFOs before
# CCR0.RE is set (FSP r_sci_b_uart open order); previously FM was set after RE

## cause (before the change)
# Symptom: SCI5 starting from reset-value registers (CCR3=0x00001203, FM=0)
# transmits the boot text but never receives: FRSR.R=0, rx_count=0, no error
# flags, while PIN(7) bit 3 toggles under host input and GIC INTID 176-179 are
# enabled and routed to CPU0. Warm reloads inherit FM=1 and never show it.
# GDB replay of the full setup sequence from SCI5 reset, two runs each:
#   C: CCR3=0x00009200 before RE, FM set after RE   -> RX dead
#   D: CCR3=0x00109200 before RE                     -> RX alive
# Toggling CCR0.RE after FM is set also recovers RX; toggling FM while RE=1
# does not break it.

## runs (after the change)
# A register reset: RST(8) 0x10420920 = 0x18000000 then 0x18001800
#   -> SCI5 read back CCR0..CCR3 = 0 / 0x10 / 0xff00ff04 / 0x1203
# B cold CPG: SCI5 reset 0x10420920 = 0x18000000, clocks gated
#   0x1042061C = 0x07C00000 (CLKMON(3) 0xf83fffff), MSTOP 0x10420D28 = 0x01000100
# C warm reload, no reset
# each: guarded reload, then idle 0x03, 3x cpuhog + 0x03 + ps, echo
# result: A, B, C all steps PASS; boot 10 lines, 0 bare LF; echo_check ALIVE (B, C)

## boot capture, first 40 bytes (python repr)
# A: b'\xf3UTTX\r\nClock enabled: domain=0 bit=5\r\nRe'
# B: b'\xf3UTTX\r\nClock enabled: domain=0 bit=5\r\nRe'
# C: b'NUTTX\r\nClock enabled: domain=0 bit=5\r\nRe'

## limits
# A and B corrupted the first boot progress byte ('N' -> 0xF3) with both the
# old and the new image; see the follow-up below for the cause and fix.
# No PX4 image, MAVLink or error injection in this run.

## follow-up: first boot byte 0xF3 (same day)
# cause: rzv_lowsetup() runs its own init only when CCR0.TE = 0 (any reset
# or power-up) and wrote LOWPUTC_CCR2_115200 = 0xff011a10. With BGDM=1,
# CKS=0 the divisor is 16, not the 32 its comment assumed, so the first byte
# left at ~230.6 kbaud. 'N' at twice the rate, sampled by a 115200 receiver,
# reads 0xf3. rzv_setup() then writes 0xb8012610 and the rest is correct.
# Warm reloads skip lowsetup (TE already 1), which is why run C was clean.
# The earlier "simulation artefact" note was wrong: a real power-up takes the
# same path. TE-off on the old image reproduced it without any CPG change:
#   b'\xf3UTTX\r\nClock enabled: domain=0 bit=5\r\nRe'
# fix: LOWPUTC_CCR2_115200 = 0xb8012610 (MDDR 184, BRME, BRR 38, BGDM),
#   the value rzv_setup() selects; 115184 baud, -0.01 %
# image: build.sh nsh, sha256 8fe8bc6e39cca6275b162585447a629e818793d9e44ad70e689135884dcf84cf
#   (built from a working tree that also held another session's uncommitted
#   hrt/irq/clock edits)
# D TE-off: GDB one-shot CCR0 (0x12802008) = 0, then guarded reload
# E cold CPG: run B recipe, RST(8) reads 0xe7ff, then guarded reload
# each: idle 0x03, 3x cpuhog + 0x03 + ps, echo; all steps PASS
# D: b'NUTTX\r\nClock enabled: domain=0 bit=5\r\nRe'
# E: b'NUTTX\r\nClock enabled: domain=0 bit=5\r\nRe'  10 lines, 0 bare LF
# echo_check after E: ALIVE
# host test: rzv2h-serial-fifo-runtime-test.py decodes the constant with the
# driver's divisor tables; fails on 0xff011a10 (230577 baud), passes on fix.
# Not done: a physical power-cycle capture; PX4 default link was blocked by
# the other session's in-progress rzv_hrt.c edits (undefined hrt symbols).
